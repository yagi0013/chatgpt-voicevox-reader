# 0.7.6 作業内容と検証

## 変更内容

- `audio_query` または `synthesis` が失敗した場合、同じ話者・同じセリフで2秒待機し、最大2回再試行する処理を追加。
- 初回を含む合計3回の取得がすべて失敗した場合だけ、ランダム配役は失敗話者を除外して再抽選し、固定配役はそのセリフをスキップ。
- 再抽選された話者にも同じ再試行条件を適用し、候補が尽きた場合は後続のセリフへ継続。
- 停止・スキップ時は再試行の待機を直ちに中断。最大3件の先読みと合成通信の順次キュー方式を維持。
- 再試行待機中は、対象話者、2秒後に再試行すること、現在の再試行回数を状態表示。

## 検証

- Windowsの一時Chromeプロフィールで `tests/regressions.ps1` と `tests/settings.ps1` を実行。
- 一時的なAPI失敗が2回続き、3回目に成功した場合、話者を変更せず再生されることを検証。
- 恒常的なAPI失敗では、3回目の失敗後にランダム配役の再抽選または固定配役のスキップへ進み、後続の再生が継続することを検証。
- 再生中の先読み、最大3件の上限、通信の直列実行、FIFO、停止時の中断・解放、接続先切替の既存回帰テストを実行。
- バージョン表記、参照アセット、公開対象ファイルの整合性を確認。

再試行はVOICEVOX Engineへの取得通信を対象とし、初回失敗後と2回目の失敗後にそれぞれ2秒待機します。API側のGPUメモリ管理やモデル解放処理は変更しません。実際のChatGPT画面・GPU・音声機器を使った通し確認は未実施です。
